## 一句话理解

throng 是“给多项目、多终端、多 AI 代理干活的人用的指挥中心”：每个项目一个独立空间，终端跑在后台服务里，关掉窗口也不会杀死构建、服务器或 AI 代理，重开就接上。

## 通俗解释

重度开发者的桌面常常是一团乱：IDE 一个窗口、好几个终端窗口（不同 shell）、文件管理器一堆、现在还要同时跑几个 AI 代理——分不清哪个窗口属于哪个项目，关错一个正在跑的长任务就没了。throng 把这些收进一个键盘优先的窗口：每个项目有独立根目录和颜色，可分组；标签页和分屏面板随意拖拽摆放，按项目保存/恢复；面板里是真实的 PowerShell、Git Bash、CMD 终端，旁边是代码编辑器、实时文件树和渲染预览。关键是终端由后台服务托管——关窗不杀进程，重开后连同 scrollback 一起恢复，甚至能续接之前的 Claude Code 会话（来源：README 开头与 “The problem it solves”、“Features”）。它还带资源监控、Attention 标记、通知面板、14 套主题等（来源：README Features）。

## 它不是什么

1. **不是 IDE 的完全替代**。它是“工作台/终端管理器”，内嵌的编辑器轻量（55 种语言语法高亮），不是功能齐全的 IDE（来源：README Features 中 editor panels 描述）。
2. **不是网页应用**。它是桌面应用，有 Windows 11 x64、Linux x64、macOS Apple silicon 的安装说明（来源：README 徽章与 docs 链接）。
3. **不是自带终端模拟器**。它用“你真实安装的 shell”（PowerShell、Git Bash、CMD），只是放在后台服务里托管（来源：README）。
4. **不是单人单项目工具**。它的核心卖点就是多项目、多面板、多代理并行管理（来源：README）。
5. **不是已达到 1.0 的稳定产品**。README 有 v1.0.0 进度徽章和 nightly/release 流水线，说明仍在开发（来源：README 徽章）。

## 痛点

- **多窗口混乱**：IDE + 终端 + 资源管理器 + 多个 AI 代理窗口混在任务栏；throng 用“每项目一个隔离空间 + 键盘切换”解决。
- **关窗杀进程**：误关窗口导致长任务中断；后台服务让终端与进程存活、可重连（来源：README）。
- **AI 代理多开失控**：同时跑十几个代理时分不清进度；Attention 标记 + 通知 + 任务栏计数帮助追踪（来源：README）。
- **布局无法保存**：throng 按项目保存/恢复面板布局，支持拆成子窗口带到第二屏幕（来源：README Features）。

## 核心功能（依据 README，注明来源）

- **项目与分类**：每项目独立根目录和颜色，键盘切换（来源：README Features）。
- **可停靠工作区**：无限标签 + 拖拽分屏，按项目保存恢复；子工作区可拆成独立窗口成组移动（来源：README）。
- **终端面板**：真实 shell，由后台服务托管，重启后重连并保留 scrollback，Claude Code 会话可续（来源：README）。
- **Attention 标记与通知**：面板/标签/项目需要你时标记，可选通知与任务栏计数，一键跳到下一个（来源：README）。
- **编辑器与文件树**：55 种语言语法高亮、崩溃恢复、每文件单一缓冲、保留编码与换行；项目级实时文件树，支持撤销的重命名/移动/删除，跨项目剪切复制粘贴（来源：README）。
- **预览与查找**：Markdown 实时渲染、滚动同步、标题大纲、Obsidian wikilinks/图片嵌入、任务列表、Mermaid 图；全项目查找替换与 Quick Open（来源：README）。
- **其他**：Focus Mode、可点击链接、资源监视器、键盘优先且可重绑定、14 套主题、自定义图标集、热重载配置（来源：README）。
- **平台与安装**：Windows 11 x64、Linux x64、macOS Apple silicon，apt/dnf 包仓库（来源：README 徽章与 docs 链接）。

## 使用场景

- 同时维护多个仓库、开多个终端和 AI 代理的开发者。
- 需要长任务（构建/服务器/代理）关窗后继续跑的工作流。
- 想要高度可定制、键盘驱动的桌面环境的人。
- 多显示器用户：把子工作区拖到副屏。

## 适用人群

命令行重度用户、多项目开发者、同时跑多个编码代理的人。轻度用户会觉得复杂。

## 注意事项

- AGPL-3.0 许可，对外提供服务需注意源码开放义务。
- 仍在向 v1.0 开发（有 milestone 徽章），76 star、无正式 release，属于早期项目。
- 桌面应用且依赖真实 shell，跨平台支持以 README 徽章所列平台为准。

## 总结

throng 抓住了“多项目 + 多代理”时代的真实痛点：窗口混乱和关窗杀进程。后台服务托管终端、按项目保存布局、Attention 标记等设计都切中要害。它仍早期且小众（76 star），但方向明确、功能面完整。对每天在终端里同时跑一堆任务的人，它值得关注；对普通用户则过于重装。
