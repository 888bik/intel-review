## 一句话理解

这是给自动化代理用的浏览器：普通浏览器弹窗抢焦点、吃内存、标签分散，而 agweb 尽量安静、轻量、一眼看全所有标签页。

## 通俗解释

AI 代理调用浏览器时，普通 Chrome 会弹窗、抢用户焦点、占大量内存，多标签管理也乱。agweb 的定位是“A browser built for agents - no focus stealing, a tiny footprint, all tabs in one view”（来源：仓库描述），用 Swift 编写（macOS 生态）。README 有 Install、Use、Compared with playwright-cli、Limits、Develop 等章节：它专门和 playwright-cli 做了对比，说明其目标用户是“需要浏览器能力但不想被浏览器打扰”的代理工作流（来源：README headings）。284 star、v0.7.0（2026-11-21），项目很新但在快速迭代。

## 它不是什么

1. **不是通用日常浏览器**。它为代理设计，强调无焦点抢占与轻量（来源：仓库描述）。
2. **不是 Chromium/Firefox 分支**。用 Swift 编写，具体内核未核实（来源：GitHub language=Swift）。
3. **不是 Playwright 的替代品**。README 专门“Compared with playwright-cli”，是对比而非同质替代（来源：README headings）。
4. **不是跨平台**。Swift + README 未提供多平台安装说明，平台以仓库为准（未核实）。
5. **不是功能齐全**。README 有 Limits 章节，明确有局限（来源：README headings）。

## 痛点

- **抢焦点**：代理开浏览器打断用户工作。
- **资源占用**：自动化场景开多浏览器实例，普通浏览器太重。
- **多标签可见性**：代理与用户都需要一眼看全标签状态。
- **与自动化工具差异**：playwright-cli 等偏测试，代理需要不同的交互模型（来源：README 对比章节）。

## 使用场景

- AI 代理需要浏览器执行网页操作时，作为“安静”的浏览器后端。
- 需要同时观察多个标签页的自动化工作流。
- macOS 上希望浏览器不打扰用户的场景（平台未完全核实）。

## 总结

agweb 抓住了一个被忽视的真实痛点：AI 代理用浏览器时“太吵太重”。无焦点抢占、轻量、单视图标签都是针对代理场景的贴心设计。它很新、平台信息不全，但与 playwright-cli 的对比说明作者对场景理解清晰。做浏览器代理的开发者值得关注。
