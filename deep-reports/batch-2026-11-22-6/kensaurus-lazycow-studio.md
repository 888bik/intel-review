## 一句话理解
Lazycow Studio 把你硬盘里一堆没时间整理的旅行或店铺素材，变成按音乐节拍剪好的竖屏短视频和带章节的长视频；AI 可以做草稿、可以排期，但发布前必须有人按下 Approve。

## 通俗解释
这是一个跑在本机的“剪辑工作室”：Node 服务负责页面与 HTTP API，Python 引擎负责编目、打标、选片段，Remotion 与 ffmpeg 负责渲染。素材只读，标记和搜索用你自己的 CPU 上的 OpenCLIP 完成，所以主流程不需要密钥、不调用大模型；只有你主动加上 key，才会用 OpenRouter 做审片建议、用 fal.ai 做慢动作或配音之类的增强。它把流程拆成可理解的积木：项目、素材、主题、短视频、风格、批准、排期、版本、长视频、图片帖、Chrome 助手和 MCP。代理可以通过 MCP、HTTP API 或 npm 包接入，能查状态、做片子、排期、发布已批准的片子，但工具列表里根本没有“批准”这一项——这是刻意设计的硬闸门。README 很长，配有逐页 GIF 导览、架构图和成本表，但项目只有 3 star，很多效果数字来自作者自述。

## 它不是什么
1. 不是云端 SaaS，默认只监听 127.0.0.1，素材、密钥和登录态都留在你自己的电脑上。
2. 不是全自动无人发布器，任何内容都要经过人工 Approve，含人脸的还要先确认同意或做模糊处理。
3. 不是通用剪辑器，它面向“从一堆素材里挑片段拼成短视频”这类重复生产，而不是精细逐帧编辑。
4. 不是必须联网的 AI 工具，主流程可完全本地运行，付费服务是可选插件式的。
5. 不是只有一个界面，它同时是本机应用、MCP 服务器、HTTP API 和可 Docker 自托管的服务。

## 痛点
- 小店、民宿、创作者手里有大量素材，却没有时间每天剪一条短片发到多个平台。
- 云端剪辑工具要求上传原始素材，隐私和带宽都成问题。
- 让 AI 自动发布很危险，品牌口径和肖像同意都需要人来把关。
- 不同平台要求的画幅、时长和文案不同，手工逐一适配耗时。
- 已排期的内容想换成更好的版本，通常要手动删除重发。

## 核心功能（依据 README，注明来源）
- 自动从照片和视频中找合适片段，按免费音乐节拍剪成竖屏 reels，也能分段生成带地图和章节的长视频（来源：README 开头）。
- 人工审批闸门：新片是草稿，未批准不能排期或发布；人脸需 Consent OK；文案变动回到复核；代理无法批准（来源：README A person approves every post）。
- 标记与搜索用本机 OpenCLIP 完成，素材只读不改不上传，服务默认只监听回环地址（来源：README Everything stays on your computer）。
- 提供 MCP 服务器、HTTP API（OpenAPI 3.1）与 npm 包，一条命令即可把 Claude Desktop、Cursor、VS Code、Claude Code 接进来（来源：README Use it from your AI tool）。
- 可发布到 YouTube、Facebook、Bluesky，并通过 Chrome 助手替你填写 X、TikTok、Google Maps、LINE、LinkedIn 的排期界面（来源：README Connect your accounts 与 building blocks）。
- 版本与自动替换：更好的剪辑做成新版本，人工选择“用新版本”后按原时段替换已排期内容（来源：README The building blocks）。
- 提供 doctor 预检、下载解压双击安装、Docker Compose 自托管，并明确列出处理器、内存、磁盘和 ffmpeg 版本要求（来源：README Quick start 与 Self-host with Docker）。
- 付费调用前先报价，默认每日 2 美元、每条 2 美元、总计 20 美元上限，免费音乐来自 Openverse（来源：README What costs money）。
- 作者用逐页 GIF 展示 Today、Workflow、Reels、Review、Posting、Results、Footage、Versions 等页面，说明当“产品导览”读很方便（来源：README Every page, in motion）。

## 使用场景
- 小型酒店、民宿、咖啡馆或店铺，想每天自动发一条短片但没人会剪。
- 旅行创作者有一大堆素材，想自动出一条 5 到 15 分钟的带章节长视频。
- 需要把同一条素材适配成多家社交平台 formats 并排期。
- 希望 AI 代理帮忙准备草稿，但保留人工发布权。
- 对素材上云有顾虑，要求所有标记与检索在本地完成。

## 适用人群
适合没有剪辑时间的小商家和内容创作者，尤其是愿意花半小时跑安装向导、机器有 8 线程以上处理器的人；追求精细剪辑、或用 Intel Mac 的用户会被门槛卡住。

## 注意事项
- 只有 3 star、2026 年 11 月 13 日创建，3.5 万字符的 README 主要由作者撰写，实际剪辑质量缺少第三方验证。
- 速度与效果数字均为自述、未独立核实：README 提到按 364 次真实构建估算每条约 357 秒，又说 9 片段短片在 32 线程机器上约 6 到 7 分钟。
- 安装约 1.3 GB（其中约 0.6 GB 是首次搜索时下载的模型），要求 Node 20、Python 3.12、ffmpeg 5.1 以上，Intel Mac 因 PyTorch 不再支持而不可行。
- Remotion 有独立许可：个人、非营利及 3 人以下公司免费，超过 3 人的营利公司需自行购买公司许可，Apache-2.0 不覆盖这部分。
- X、TikTok、Google Maps、LINE、LinkedIn 靠 Chrome 里自动填写网页排期，稳定性取决于页面结构与登录状态，不是官方 API。
- 代理“没有批准工具”是刻意限制，若想全自动发布，需要自己改代码，这会破坏其安全模型。
- Windows 被作者称为日常使用平台，macOS 与 Linux 主线可用但测试较少。

## 总结
Lazycow Studio 的完成度远超它的 star 数：素材检索、自动剪辑、人工审批、多平台排期、版本替换和代理接入串成了一条完整流水线，而且把“人必须批准”和“素材不出本机”写成了架构约束而非口号。它仍然很新，3 star、安装体积大、硬件门槛清晰，部分平台靠浏览器自动化而非官方接口，性能与效果都需要你自己跑一遍才能确认。对有稳定更新需求的小商家和创作者，值得花时间试；把它当万能剪辑器则会失望。
