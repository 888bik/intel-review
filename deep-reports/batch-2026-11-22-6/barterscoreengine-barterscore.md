## 一句话理解
BarterScore 是一个纯 JavaScript 的离线计算库加参考目录：它给大米、药品、电池等生活物资以及焊接、翻译等人类服务各算一个易货分，再按场景算两件东西之间应该怎么换，目标是供应链中断、人道危机或社会崩溃时仍能在断网断电的纸上使用。

## 通俗解释
项目的定位很特别：一个为崩溃信息学与离网经济设计的本地优先数学引擎。整个架构用原生 ES6+ UMD 写成，可在 file:// 协议下双击打开，也可作为 CommonJS 或 ES Module 使用，不依赖 Node、服务器或网络。README 非常长（五万余字符），详尽到令人惊讶：从营养指数 IN、基础分 ScoreBase、外部情境修正 MEC 的公式，到「1 分」的物理定义，再到 USDA、WHO、Sphere 手册等离线审计来源，以及 128 个条目（100 种实物加 28 种服务）的追溯矩阵，还附了九种语言的文档与可打印的模拟野外手册。但必须说清楚：它最大的不确定性也在这里——公式里的等效能量基 EEB、准备成本、心理因素、脆弱度等桥接标度是项目自称由设计论证、无外部来源的原创工程标度，把抗生素、大米、贵金属放在同一条数轴上的做法属于项目自述、未独立核实，不宜当作经过验证的经济学或营养学模型。项目仅 7 星、0 fork，尚无社区检验。

## 它不是什么
1. 它不是真实市场价或货币汇率：分数来自自定公式与参数，不是成交数据或官方统计。
2. 它不是经过同行评议的科学模型：README 明确区分官方来源与无外部来源的工程启发式，后者占核心位置。
3. 它不是记账或库存 App：核心是一套计算引擎加条目目录，界面主要用于生成手册与模拟交易。
4. 它不是云服务：恰恰相反，它强调 file:// 双击运行、完全离线、零运行时依赖。
5. 它不是通用物资数据库：128 个条目是参考基线，地区化需要用户自己加 Item 129+ 并维护审计记录。

## 痛点
- 危机或断网环境下，没有可靠价格信号，人们难以判断一公斤米和一板抗生素怎么等价交换。
- 营养、药品、物流的真实数据散落在不同标准体系里，单位互不兼容，难以放在同一尺度比较。
- 灾区或离线场景无法联网查数据库，需要能打印成纸、断网也能算的工具。
- 以物易物中对方物品常不可拆分，算出的精确数量无法执行，需要明确的找零建议。
- 多语言与本地药品命名差异大，统一目录若不能本地化就难以落地。

## 核心功能（依据 README，注明来源）
- 评分公式：营养指数 IN 限制在 0.5 至 2.5，基础分把能量、重量体积、保质期对数、准备成本、士气与包装韧性组合，最终分再乘情境修正（来源：README The Official Mathematical Formula）
- 两种危机情境：急性崩溃压低价值储存类物品至 0.01 倍并抬高水、止血药、抗生素等生存物资，经济重建则把价值储存类抬到 5.0 倍（来源：README External Context Modifier & Final Score）
- 双边交换计算：calculateTrade 给出精确数量、推荐整数单位与不可分物品的价值偏差警告及找零建议（来源：README Bilateral Exchange Parity & Indivisibility Alert）
- 128 条标准目录：100 种实物商品加 28 种人类服务，按九类独立短码前缀管理，便于无线电或纸面记录（来源：README Schema Contract、9 Category-Isolated Short Code Prefixes）
- 离线审计档案：USDA FDC 编号、WHO ATC 代码等查询记录永久保存在 audit_sources/，可离线核验基线（来源：README Scientific Methodology、Offline Audit Sources）
- 一键离线启动与纸质手册：Windows 批处理与 Unix 脚本直接打开 manual_generator.html，可打印 A4 横向的黑白野外手册（来源：README 1-Click Offline Launch、Physical Paper Manual Printing）
- 开发者 SDK：浏览器 script 标签、ES Module、CommonJS 三种用法，支持 registerCustomItems 扩展与 registerLocale 本地化（来源：README Developer Integration Guide、Adding Item 129+）
- 多语言与回退链：九种 BCP 47 语言包，未翻译键自动回退英文再回退技术 ID（来源：README Core Architectural Principles、Adding a New Localization Pack）

## 使用场景
- 灾前为社区准备可打印的换算手册，断电断网时按纸面表格完成以物易物。
- 人道救援或备灾场景中，为物资与关键服务的相对价值讨论提供一个可讨论的量化起点。
- 在离线应用或嵌入式环境里，用 UMD 模块做确定性的估值计算，无需后端。
- 为特定地区扩展条目与语言包，把本地药品命名和物价纳入目录。
- 模拟两件物品的交换，查看不可分物品带来的价值偏差与找零建议。

## 适用人群
适合备灾与离网社区的组织者、人道援助与互助网络的技术支持者，以及对本地优先、零依赖架构感兴趣的 JavaScript 开发者。它需要使用者接受分数是模型输出而非市场事实这一前提，并愿意按本地区校准参数；把它当权威定价依据的普通用户会失望。

## 总结
BarterScore 是一次野心很大、工程表达完整的尝试：它试图用确定性的离线公式，把危机中原本只能在混乱里讨价还价的物资交换，变成一个可计算、可打印、可审计的流程。零依赖 UMD、file:// 直开、多语言回退、纸质手册和开发者 SDK 这些设计都考虑得很周到。但从深度解读的角度必须点明，它的核心效力依赖于一组没有外部来源自证的参数体系，128 条目录的科学可追溯性也主要靠项目自称的档案。对 7 星的全新项目而言，这更适合作为思路参考和社区讨论起点，而不是可以直接信赖的决策工具。
