## 一句话理解
aq（attention-queue）是给 tmux 里多个 Claude Code 会话用的注意力队列：它用 hooks 监听这些会话，把待审批的改动、待审阅的 diff、权限询问和问题变成一张张卡片排进同一个队列，你一次只处理一张，处理完再看下一张。

## 通俗解释
作者的痛点很具体：自己在 tmux 里开了好几个 Claude Code 会话，老是需要人介入，却总搞不清哪个在等自己。aq 的做法是做一个独立的 TUI，坐在终端里盯着所有会话，谁来消息就排成卡片，且不会抢走你正在看的屏幕——新卡片会排队等轮到它。每张卡片对应一种交互：审阅卡像 PR 一样在 diff 的具体行上留言再一次性发回；step 模式把每次编辑拆开让你逐条同意；quiz 模式就改动向你提问，答不上来会被追问；vibe 模式则完全不查。权限请求会附一行 Haiku 生成的说明，按 y 放行；合并、推主分支、强推、以你名义发评论等代你执行的动作在任何模式下都要单独确认。项目还做了 GitHub PR 审阅、会话总览、旁路提问（用会话副本回答，原会话看不到）、新建会话与 worktree、会话间经 aq tell 传话等能力。设计上很克制：通过 Claude Code hooks 接入，aq 没开时 hooks 什么也不做，Claude 照常运行。README 有完整对比表，坦承把分支与合并留给用户和 Claude，这和全包式工作台形成对照。项目 13 星、0 fork，发布到 v0.1.12。

## 它不是什么
1. 它不是会话调度器：不替你管理分支与合并，也不接管会话的创建方式，只是把需要你的事项排好队。
2. 它不是 Claude Code 的替代品：依赖 Claude Code 的 hooks 机制，aq 不在运行时原会话照常工作。
3. 它不是 IDE 或浏览器工具：是 Linux 终端里的 TUI，且要求在 tmux 中使用。
4. 它不是侧重安全审计的沙箱：受保护动作需要你确认，但代码执行仍发生在你的会话与环境里。
5. 它不是全平台方案：只支持 Linux、tmux 与 Claude Code，GitHub PR 功能还要求安装并登录 gh。

## 痛点
- 多个 Claude 会话同时等待人工介入，很难知道哪个卡在权限、哪个已经写完待审。
- 切到某个会话处理时，另一个会话的新请求会抢走屏幕，打断当前工作。
- 逐条审批编辑、逐 turn 审阅、对改动做理解测验，不同项目需要不同强度，难以一刀切。
- 合并、推送等以你名义执行的动作，在自动化流程里容易被悄悄放行。
- 重启或断电后，未发送的评论与正在跟踪的会话状态容易丢失。

## 核心功能（依据 README，注明来源）
- 统一队列：把各会话的 diff、编辑、权限请求与问题汇成卡片，一次一张且新卡排队不抢屏（来源：README Key features、作者自述段落）
- 审阅模式：每个项目可选 review 每 turn 审阅、step 逐编辑批准、quiz 就改动提问、vibe 不检查（来源：README Key features、Modes）
- 类 PR 审阅与权限卡：在 diff 行上留言并一次发回，权限请求附 Haiku 摘要，按 y 放行（来源：README Review card、Permission card）
- 受保护动作：合并、推主分支、强推与以你名义发的评论在任何模式下都等一个确认（来源：README Flagged actions）
- GitHub PR 审阅：按 R 打开未合并 PR 作为审阅卡，评论可回会话修复或作为一次 PR review 提交（来源：README PR review）
- 会话总览与旁路提问：无待办时在标签页里看各会话，W/T/? 分别问进度、让 Haiku 总结、问任意问题，且用会话副本回答（来源：README Sessions view、Side questions、First keys）
- 会话与工作区管理：N 新建会话，可建独立 worktree；O 为目录下每个仓库开一排标签页；会话间可用 aq tell 传话并先经你批准（来源：README New sessions、Messages）
- 持久化与键盘优先：未发送评论在重启后保留，重启系统后重开原会话；vim 键位与首次运行的模拟卡片教学（来源：README Key features）

## 使用场景
- 在 tmux 里同时跑多个 Claude Code 会话，用单一队列处理所有需要你拍板的事项。
- 对关键项目开启 review 或 step 模式，逐 turn 或逐编辑把关代理产出。
- 用 quiz 模式检验自己对代理改动的理解，或让权限卡用一行摘要解释工具调用再决定是否放行。
- 在队列空档通过标签页总览各会话，发消息、切模型或停止某个会话。
- 用 R 审阅 GitHub PR，让意见直接进入会话或作为正式 review 提交。

## 适用人群
适合在 Linux 上用 tmux 同时运行多个 Claude Code 会话、且希望保持键盘流的开发者。需要接受通过修改 ~/.claude/settings.json 注入 hooks、重启既有会话等操作步骤；不用 tmux 或不用 Claude Code 的人无法使用，偏好由应用全权管理分支合并的人更适合看其他工具。

## 注意事项
- 环境与工具链限定严格：Linux、tmux、Claude Code；GitHub 功能额外需要 gh 登录。
- 安装 hooks 时要合并进已有的 PreToolUse、PostToolUse、PermissionRequest 数组，直接替换会让你原来的 hooks 失效；修改前建议备份。
- 加入 hooks 后需要重启此前运行的 Claude 会话，否则旧会话不会触发新 hooks。
- 配置与状态分别位于 ~/.config/aq/config.toml 与 ~/.local/state/aq/；仓库提供 cargo test（含私有 tmux 服务器上的端到端测试）与无需登录的演示录制脚本。
- 许可证为 MIT；项目 13 星、0 fork，发布到 v0.1.12，社区验证有限。

## 总结
aq 的优点是克制和聚焦：它不试图接管会话生命周期，而是用 hooks 做一个谁来找我就排队的终端前台，把审阅、逐步批准、测验、权限确认与受保护动作统一成卡片交互，并且把重启恢复、旁路提问、worktree 新建、PR 审阅这些周边体验都补齐了。README 的对比表和分支合并留给用户的说明，反而让定位更可信。代价是强绑定 Linux、tmux 与 Claude Code，13 星、0 fork 也说明它还在早期。对正好在这个工作流里的人，它是能立刻减轻注意力负担的实用工具；其他人可以把它当作多代理交互设计的一份参考样本。
