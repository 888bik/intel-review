## 一句话理解
PocketOps 是 SigNoz 的第三方手机客户端：在 iOS 或 Android 上连到你的 SigNoz 服务地址并填一个服务账号 API Key，就能查告警、日志、服务性能、指标和仪表盘，还能把 SigNoz 链接直接粘进应用打开对应页面。

## 通俗解释
可观测性平台通常假定你坐在电脑前，但值班场景中人往往不在电脑旁。PocketOps 把 SigNoz 的主要浏览能力搬进手机：Expo SDK 58 加 Expo Router 做界面与路由，TanStack Query 管数据，API Key 存在系统钥匙串或密钥库里，没有登录流程——Viewer 角色就够浏览，想保存视图才需要额外权限。README 里相当务实地写了两类环境：一是自带的 mock 服务（按 SigNoz OpenAPI 规范造数据），适合跑单元测试和界面；二是用 foundryctl 起一个真实的本地 SigNoz，配合 seed 脚本灌入五个服务的链路、日志、指标，甚至模拟约 140 个不同命名的指标。作者特别指出 mock 隐藏了真实服务端的一些行为（乱序时间桶、任意顺序的聚合），所以涉及 API 的改动要用真实例子测。应用还支持保存视图（日志、链路、指标查询可存可改，权限由 authz/check 决定）与仪表盘只读浏览（变量、折叠面板、图表展开下钻，最多四个并发面板请求）。项目 13 星、1 fork，没有 release，提交停在 11 月中旬。

## 它不是什么
1. 它不是 SigNoz 官方产品：README 明确标注为独立项目，与 SigNoz 无隶属关系。
2. 它不是完整的可观测性后端：只做浏览与客户端侧展示，采集、存储、告警规则配置都在 SigNoz 端。
3. 它不是写入型工具：仪表盘编辑、SQL/PromQL 面板、阈值样式尚不支持，主要是查看器。
4. 它不是 Web 应用的简单封装：目标是 iOS 与 Android，web 构建只是开发便利，凭据存在 localStorage。
5. 它不是无需配置的成品：需要你提供服务地址和有合适权限的服务账号 Key。

## 痛点
- 值班告警响起来时，人往往不在电脑前，手机上看不了链路和日志就得靠猜。
- SigNoz 官方移动端体验不足，第三方客户端可填补空白。
- 手机端直接套用桌面端图表与交互往往体验糟糕，需要专门做折叠面板、分页、下钻等适配。
- 保存视图与仪表盘涉及细粒度权限，客户端必须按权限隐藏写操作，否则会报错或越权。
- 本地开发没有真实服务端时，mock 与真实行为的差异常常导致假通过。

## 核心功能（依据 README，注明来源）
- 核心浏览面：告警、日志、服务（APM）、指标，以及粘贴 SigNoz 链接打开对应界面的标签页（来源：README 开头介绍）
- 连接与凭据：服务地址加服务账号 API Key，Viewer 角色可浏览，保存视图需 saved-view 创建/更新权限，Key 存设备钥匙串/密钥库（来源：README 开头介绍）
- 保存视图：Logs、Traces、Metrics 中加载与保存视图，保留过滤、聚合、分组与排序，支持更新、另存与离开视图（来源：README Saved views）
- 仪表盘只读浏览：读取 /api/v2/dashboards，保留分区顺序，支持变量共享时间范围、面板展开取值与日志/链路下钻（来源：README Dashboards）
- 权限感知：写按钮在 /api/v1/authz/check 确认权限后才显示，权限判断缓存并在一分钟后刷新（来源：README Saved views）
- 本地开发与测试链路：vitest 单元测试、tsc 与 expo lint、按 OpenAPI 造的 mock 服务、foundryctl 起真实实例与 seed 脚本（来源：README Run it、Test against a real SigNoz locally）
- 技术栈与发布方式：Expo SDK 58、Expo Router、TanStack Query，构建仅本地 eas build --local，JS 变更走 eas update（来源：README 开头介绍）

## 使用场景
- 值班或通勤时从手机查看 SigNoz 告警与告警对应服务的链路、日志和指标。
- 在 Logs/Traces 里打开保存的查询视图，查看分页结果并进入详情与关联链路。
- 在 Metrics 里查看保存的图表或公式视图，按图表、表格、数值模式切换并保留时间范围。
- 打开团队仪表盘，展开面板查看数值并下钻到对应日志或链路。
- 在本地用 mock 或 foundryctl 起的真实例子做开发与回归测试。

## 适用人群
适合使用 SigNoz 的 SRE、运维与后端开发者，尤其是经常值班、需要随时随地查监控的人。要求你有一个可访问的 SigNoz 实例和能生成服务账号 Key 的权限；只使用其他监控平台、或希望在手机上编辑仪表盘的用户不适合。

## 注意事项
- 项目 13 星、1 fork，最新 release 返回 404（由 writer 统一说明），提交停在 2026 年 11 月 14 日，尚处早期。
- 无登录流程，Key 权限决定可见功能；保存视图需要 saved-view:create 与 saved-view:update 权限，旧服务端若缺少 authz/check 会隐藏写操作。
- web 构建仅为开发便利，凭据存 localStorage；README 说明 mock 按 OpenAPI 规范构造，无法发现与真实服务端的语义分歧。
- 仪表盘为只读查看器：编辑、SQL/PromQL 面板与阈值样式不支持，未知插件会显示不支持状态；面板最多 4 个并发请求，卡片显示 4 行、展开最多 200 行、图表最多 50 条序列。
- 许可证为 MIT。

## 总结
PocketOps 的价值主张很直接：把 SigNoz 的排障入口从工位延伸到口袋。它并没有只做一个粗糙的网页壳，而是在保存视图、权限感知、仪表盘变量与下钻、并发与截断策略等细节上做了认真适配，还配了 mock、seed、CORS 代理一整套本地开发链路，工程意识强于常见的第三方客户端。限制也很明显：它是只读为主的独立项目，不是官方支持，没有 release，13 星的社区规模还不足以证明长期维护能力，真实服务端的行为差异仍需自己验证。对已经用 SigNoz 且常值班的人来说，它值得一试；对其他人，先把它当作一个实现质量不错的参考项目。
