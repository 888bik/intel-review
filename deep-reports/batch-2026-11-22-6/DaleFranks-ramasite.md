## 一句话理解
RamaSite 是一个自包含的内容管理系统：所有内容在一个 SQLite 文件里、图片在站点的 uploads 目录，不需要另外连数据库服务器，把 release zip 上传到普通 cPanel 共享主机、走完安装界面就能用。

## 通俗解释
名字来自阿瑟·克拉克的小说《与拉玛相会》——拉玛是一个自给自足的密封圆柱世界，正好对应产品理念。README（约 5500 字符）说：内容集中在一个 SQLite 文件，图片放在站点目录内；没有数据库服务器、外部服务、命令行或配置文件要改；安装就是把一个 release zip 传到普通共享主机（Apache 加 cPanel）并填安装界面。它用 Markdown 写页面、博客和文章，菜单由页面生成；有卡片、模块和轮播，图片与文件库可替换文件而不改引用它的页面，带提交存储与邮件通知的表单，可放任意位置的社交链接行，主题界面管 logo、颜色、Google Fonts、页头页脚和可选顶栏而不用改模板代码；页面移动时自动加重定向，还有自动 sitemap、robots.txt、每博客 RSS、分析/搜索验证（GA、GTM、Meta Pixel、Search Console、Bing，排除自己访问）、多管理员、可选两步登录、邮件重置密码、HTTPS 强制、一键备份与升级后自动更新数据库。底层是 Laravel、Filament 与 SQLite。10 star、2026-10-28 创建、有 v1.3.0 release，仍在早期。

## 它不是什么
1. 不是需要独立数据库服务器的 CMS——它刻意用单文件 SQLite，适合共享主机。
2. 不是静态站点生成器——内容在后台管理、运行时由 PHP 渲染。
3. 不是博客专用工具——文章只是其中一部分，还有页面、卡片、表单、主题等。
4. 不是上传即用的免配置玩具——仍需 PHP 8.4.1 以上和若干扩展、SQLite 3.26 以上、Apache mod_rewrite，并填安装密钥。
5. 不是多站点管理平台——面向单个站点部署。

## 痛点
- 共享主机通常不给独立数据库服务器或命令行权限，装主流 CMS 很麻烦。
- 上传 zip 里的 Source code 包不能独立运行，用户容易下错文件。
- 升级 CMS 时最怕覆盖内容和设置，也怕数据库结构变更失败。
- 想改主题常要碰模板代码，对非开发者门槛高。
- 页面搬家后旧链接失效，需要手动维护重定向。

## 核心功能（依据 README，注明来源）
- 单文件自包含：所有内容在一个 SQLite 数据库，图片在站点 uploads 目录，无数据库服务器、外部服务、命令行或配置文件（来源：README 开头设计要点）。
- Markdown 内容与页面构建：页面、博客、文章用 Markdown 写，菜单由页面生成；卡片、模块、轮播可在不写 HTML 的情况下搭页面（来源：README What it does）。
- 媒体与表单：图片和文件库可替换文件而不改引用页面，支持嵌入 YouTube、带提交存储与邮件通知的表单、可放任意位置的社交链接行（来源：README What it does）。
- 主题与界面定制：Theme 界面管 logo、颜色、精选 Google Fonts、标题、页头页脚和可选顶栏，无需编辑模板代码（来源：README What it does）。
- SEO 与运维自动化：自动 sitemap、robots.txt、每博客 RSS、页面移动自动加重定向、Google Analytics 等接入并排除自己访问、一键备份、升级后数据库自更新（来源：README What it does）。
- 账号与安全：多管理员、可选两步登录、邮件重置密码、HTTPS 站点强制 HTTPS（来源：README What it does）。
- 简易安装与升级：上传 release zip 到 public_html、填 setup-key.txt 中的密钥完成安装；也可用 Composer create-project；升级只需备份、覆盖文件、访问站点自动迁移（来源：README Installing / Upgrading / Installing with Composer）。

## 使用场景
- 只有 cPanel 共享主机、没有独立数据库或 SSH 的个人或小企业建站。
- 想用 Markdown 写博客、同时需要表单和文件库的轻量内容站。
- 需要在后台直接换 logo、颜色和字体而不改代码的非开发者。
- 希望升级时自动备份和迁移数据库、不覆盖自己内容的小站维护者。

## 适用人群
共享主机用户、小企业主、博客作者、怕碰代码和数据库配置的人；也适合想读 Laravel 加 Filament 如何做零配置 CMS 的 PHP 开发者。不适合需要多数据库、复杂权限或高并发的大型站点。

## 注意事项
- 仅 10 star、0 fork，2026-10-28 创建，有 v1.3.0 release（2026-11-19），仍属早期，社区验证有限。
- 必须下 Releases 里的 ramasite 版本 zip，不能用 Source code 下载，后者不能独立运行。
- 环境要求较硬：PHP 8.4.1 以上、SQLite 3.26 以上、Apache mod_rewrite，以及 pdo_sqlite、mbstring、intl、openssl 等一系列扩展；不满足时首页会用可转述给主机的文字说明。
- 首次访问需打开上传目录里的 setup-key.txt 填密钥；安装完成后该文件会被删除。
- 升级前先到 Backup 页下载备份；内容、图片、设置和账号不在 release zip 里，正常覆盖不会丢，但仍应先备份。
- 开发者构建用 GitHub Actions 在打 v 标签时自动跑测试与安全检查、发布带 vendor 的 zip；带连字符的标签发预发布。

## 总结
RamaSite 把自包含做成了明确卖点：一个 SQLite 文件加一个上传目录，配上 cPanel 共享主机就能跑，把主流 CMS 的部署门槛降下来。功能覆盖页面、博客、表单、文件库、主题、SEO 与备份升级，对一个 10 star 的新项目来说完成度不低。局限也很清楚：环境要求不低、生态很小、尚无充分社区验证。适合共享主机上的轻量站点；需要复杂权限或高并发的人应另选成熟方案。
