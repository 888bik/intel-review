## 一句话理解
一个 Python 命令行工具：不看 GPS 和时间戳，只凭一段夜空延时视频反推它在哪里、什么时候拍的，并给画面里的卫星轨迹命名。

## 通俗解释
README 把原理讲得很清楚：恒星定镜头、指向和帧间隔，天际线定大致纬度，行星或彗星给夜晚定日期，卫星轨迹与当晚所有编目目标的轨道比对，多条轨迹交汇处就是地点、时间与曝光。README 内容充实，2 star，刚入库，尚无社区验证。文中速度与精度数字均为自述、未独立核实。

## 它不是什么
1. 不是通用的视频地理定位工具，只处理带卫星轨迹的夜空延时。
2. 不从文件元数据或 GPS 读取答案，全部靠画面盲解。
3. 不是天文台级测量，结果是带置信度和偶然匹配估计的拟合值。
4. 不识别飞机轨迹，README 明确说飞机不算。
5. 没有 Release（返回 404）。

## 痛点
- 延时摄影可能暴露拍摄位置，作者还提供配套的轨迹移除项目。
- 没有 GPS、没有时间戳、文件名也无提示时几乎无法定位。
- 卫星轨迹数量少或横跨帧数不足就无法求解。
- 轨道根数需要 Space-Track 账号或自行准备 TLE，30 天以外的根数会被忽略。

## 核心功能（依据 README，注明来源）
- 从视频里提取卫星轨迹并与当晚所有编目目标轨道匹配，输出经纬度、高度、时钟、曝光以及每条轨迹的名称与置信度（来源：README How it works）
- 提供 run、trails、solve、report、replay、scan、moon、gui 等子命令，结果落在 stem.skyfind 目录（来源：README Use）
- 支持 --tle 文件或 Space-Track 凭据下载根数，并提供 --around、--free-site、--interval、--recorded 等选项兜底（来源：README Orbital elements）
- 可选 NVIDIA GPU 加速（CuPy），并可通过 SKYFIND_GPU=0 关闭（来源：README Speed）
- 星表、星历、地图图层和彗星轨道首次使用时下载到 SKYFIND_DATA，另有 android 目录跑同一套管线（来源：README Data）

## 使用场景
- 想验证自己的夜空延时是否泄露了拍摄地点
- 手里有带卫星轨迹的延时素材，想知道拍于何时何地、轨迹分别属于哪颗卫星
- 没有行星入镜时，用 --around 给定大致 UTC 再盲解
- 想借助 CLAUDE.md 让 Claude Code 帮忙跑求解或解释结果

## 适用人群
天文摄影爱好者、对轨道反推感兴趣的技术玩家，以及关心延时视频隐私泄露的人。需要精确定位服务的普通用户用不上。
