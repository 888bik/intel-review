## 一句话理解
给编码代理的技能与 MCP 服务器做一个包管理器：把选中的技能钉住到具体提交、把 MCP 配置整理成一份可分享的清单，然后在任意项目里一次性装进多个代理。

## 通俗解释
随着代理技能生态变多，逐个仓库复制技能目录、手动改各家的 MCP 配置很快变成负担。skillset 的解决办法是维护一个叫 Skillset 的 JSON 清单：技能记录来源仓库与精确提交，MCP 服务器记录运行或连接方式，清单可以放在用户主目录供所有项目复用，也可以作为项目里的 skillset.json 提交给团队。安装时它把技能写进各代理识别的目录，把 MCP 服务器写进各代理自己的配置文件，并且是增量式的，不会删除清单之外已有的东西。

它本身并不重新实现技能安装，而是包装 Vercel 的 Skills CLI，因此技能会落在与 npx skills 相同的代理目录和锁文件里。仓库描述强调省 token：只安装需要的技能，而不是把所有能力一次性塞进上下文。使用流程很短：全局安装或用 npx 运行，skill add 从 GitHub 仓库挑技能并钉住提交，mcp add 从官方 Registry 搜索或手写本地与远程服务器，进入项目后 install 即可。安全方面，清单不保存密钥，命令行只接受变量名，写入代理配置时变成环境变量引用，安装结束再提示用户设置对应变量。

README 也给出几条务实提醒：代理配置路径来自各家文档，尚未在真实代理上逐一验证；运行中的 Claude Code 会重写自己的配置文件，全局安装前最好先关闭；项目本身不采集数据，但底层 Vercel Skills CLI 会发送匿名遥测，可用环境变量关闭。14 star、2 fork、16 个未解决问题，说明它处在活跃但还在磨合的阶段。

## 它不是什么
1. 不是技能市场或技能作者平台，它只负责挑选、钉住与安装已有技能。
2. 不是 MCP 服务端，它只把服务器配置写进各代理的配置文件，不代理任何请求。
3. 不是完全独立的实现，技能安装依赖 Vercel 的 Skills CLI，行为会受上游影响。
4. 不是自动同步工具，除非运行 skill up 或 mcp up，否则钉住的版本不会改变。
5. 不是零风险配置器，README 承认代理配置路径未经真实验证，且可能覆盖同名 MCP 服务器（安装前会询问）。

## 痛点
- 同一个开发者在多个项目里重复安装同一批技能，版本还各不相同。
- 技能来源随时更新， instal 时拿到与审阅时不同的代码，难以审计。
- 不同代理的 MCP 配置格式和路径不一致，手工维护容易出错。
- 团队无法把代理技能与 MCP 配置纳入版本控制与代码评审。
- 密钥容易被误写进配置文件，造成泄露。

## 核心功能（依据 README，注明来源）
- 把技能钉住到精确 Git 提交，只有执行 skill up 才更新（来源：README Skills 段落与 Pins 说明）
- 从官方 MCP Registry 搜索或手写本地、远程服务器配置，清单不保存密钥（来源：README MCP servers）
- install 时把技能写入通用代理目录及检测到的代理，把 MCP 写入各代理自己的配置，并保留注释与无关设置（来源：README Skills 与 MCP servers 的 Install 说明）
- 支持用户级命名清单与项目内 skillset.json，也可从本地 JSON 路径或 HTTPS URL 安装（来源：README Quick start 与 Commands 段落）
- 安装是增量式的，不会移除清单以外的已有内容；同名 MCP 服务器替换前会询问（来源：README 首段特性列表与 MCP servers）
- 支持 claude-code、cursor、github-copilot、opencode、gemini-cli、windsurf、kiro-cli、roo、amp 等代理（来源：README MCP servers 中 Agents 列表）
- 提供 skill、mcp 的 add/rm/up 与 list、install 命令及 JSON Schema（来源：README Commands）

## 使用场景
- 在多台机器和多个项目之间保持一致的代理技能组合。
- 团队把推荐的技能与 MCP 配置作为 skillset.json 提交并评审。
- 尝试某个新技能前先钉住提交，确认安全后再升级。
- 为多个代理批量写入同一份 MCP 服务器配置而不手改 JSON。

## 适用人群
重度使用编码代理、维护多套技能与 MCP 配置的开发者，以及需要把代理工具链纳入版本控制的小团队。只用单一代理、技能数量很少的用户收益有限。

## 注意事项
- 代理配置路径来自文档，README 明确说未在真实代理上验证；全局安装前建议关闭正在运行的 Claude Code。
- install 技能默认写入通用目录与检测到的代理，想自定义需显式指定代理与全局或项目范围。
- 项目自身不采集数据，但底层 Vercel Skills CLI 发送匿名遥测，需要设置 DISABLE_TELEMETRY 或 DO_NOT_TRACK 关闭。
- 需要 Node.js 22.20.0 或更高版本以及 Git；私有仓库依赖本机 Git 凭据。
- 14 star、2 fork、16 个未解决问题，v0.3.0 发布于 2026-11-16，仍在快速迭代。

## 总结
skillset 解决的是代理技能变多之后的管理问题：用一份可钉住版本、可分享、增量的清单，把技能与 MCP 配置的安装变成一步操作。它的设计很克制——包装现成的 Skills CLI、不保存密钥、不覆盖无关配置，这些取舍值得同类工具借鉴。局限也很明确：能力依赖上游、代理配置路径未实测、仍有不少未解决问题。对于同时维护多个代理与多套技能的用户，它已经能省下大量重复劳动；对轻度用户，直接手工管理可能更简单。
