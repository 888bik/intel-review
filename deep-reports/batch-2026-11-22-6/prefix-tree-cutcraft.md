## 一句话理解
UberScene 把“剪视频”变成“写代码”：一个 TSX 文件就是整条片子，片段、字幕、音频、转场、特效甚至 three.js 场景都在里面，浏览器里能看、时间轴上能改，最后直接导出 MP4。

## 通俗解释
GitHub 上这个仓库的实际名称是 prefix-tree/uberscene（任务给定的名字 prefix-tree/cutcraft 会重定向过去），README 里通篇写的是 UberScene。它的核心主张是：视频应该像代码一样被版本管理——可以在 pull request 里审查，可以一次生成上百个变体，也可以让 AI 代理直接改文本。传统剪辑里你说“从讲到周五那句话开始”，剪辑软件要你把时间换算成秒；在这里你写 in="word:12"，库自己算出对应帧。同一份文件既是代理编辑的源码，也是你在时间轴上拖动的工程，两边改动都写回同一个文件且可撤销。导出不走 FFmpeg，而是在 headless Chrome 里绘制并编码；另有实验性的 Rust 原生编解码器，需显式打开开关。README 明确警告项目处于 work in progress，API 会一直到 1.0 前以破坏性方式变化，属于思路清晰但尚未稳定的作品。

## 它不是什么
1. 不是传统时间轴剪辑软件的替代品，它更像给代码作者和 AI 代理用的视频框架。
2. 不是 FFmpeg 命令行封装，导出在 headless Chrome 中绘制编码，原生编解码器是另一套实验路径。
3. 不是只能加文字的动画库， clips、字幕、音频、转场、效果和 three.js 场景都在同一个文件里。
4. 不是稳定发布的成熟工具，作者写明 API 会在 1.0 前反复变动，并靠 lint --fix 迁移文件。
5. 不是只有文本 DSL，它同时提供可复制进你自己应用的 shadcn 编辑器界面。

## 痛点
- 视频工程是二进制或私有格式，无法像代码一样 diff、review、生成变体。
- AI 代理擅长写文本，不熟悉 ffmpeg 参数与鼠标时间轴，难以直接参与剪辑。
- 剪辑点与台词、镜头强相关，按秒写死的位置在素材一变就全乱。
- 代理编辑和人工微调往往需要两套工具，改动难以同步和撤销。
- 导出要装 FFmpeg 和一堆 C 库，环境配置门槛高。

## 核心功能（依据 README，注明来源）
- 一个 TSX 文件即整条视频，用 Composition、Track、Clip、Transition 描述剪辑，支持 React、Motion 与 three.js 层（来源：README Example）。
- 剪辑点用台词或镜头命名而非秒数，例如 in="word:12"，素材变动后所有标注跟着词走（来源：README Why 与 Example）。
- 浏览器中播放、时间轴上调整、导出 MP4，另有 WebM、ProRes、音频或静帧的输出目标（来源：README 开头与 Why）。
- 无 FFmpeg，导出在 headless Chrome 中绘制编码，MIT 许可、无付费档与水印（来源：README Why）。
- 实验性原生编解码器用 Rust 实现，基于 craft-video、craft-media、craft-audio，可解码 H.264、HEVC、VP8、VP9、AV1、ProRes、DNxHR 并编码 H.264、ProRes 与音轨，默认关闭（来源：README Native codecs）。
- 3D 场景与相机路径跑在视频同一条时间轴上，路线图还包含深度、遮罩、姿态引导通道与 glTF 导出到 Blender（来源：README Aim）。
- 编辑器基于 shadcn/ui，以源码形式复制进你的应用，拖拽移动或裁剪片段，改动只写入文件里对应的那个值并全部可撤销（来源：README Editor）。
- 给代理提供 skill 安装方式，可用 Claude Code 插件市场或 npx uberscene skills install，然后用自然语言下达剪辑任务（来源：README Install）。
- 路线图明确标出已完成、进行中和计划中的能力，包括引导通道、glTF 导出等仍未落地部分（来源：README Aim）。

## 使用场景
- 需要按台词批量生成竖屏短视频、广告变体的内容团队。
- 让 AI 代理根据脚本直接产出视频草稿，再由人微调。
- 希望视频工程进 Git、在 PR 里审查改动的开发型团队。
- 需要在同一时间轴上对齐剪辑、三维场景与生成式视频模型输入的研究者。
- 想避开 FFmpeg 依赖、在纯 Node 环境里完成导出的场景。

## 适用人群
适合熟悉 React 与 TSX、愿意接受早期 API 变动的开发者，以及希望让编码代理参与视频生产的技术型创作者；不熟悉代码、要求稳定界面的传统剪辑用户暂时不是目标受众。

## 注意事项
- GitHub 实际仓库名是 prefix-tree/uberscene，任务给定的 cutcraft 只是入口名称，查阅文档请以实际名称为准。
- 49 star、2026 年 10 月 25 日创建，README 自述处于 work in progress，API 会在 1.0 前持续以破坏性方式变化。
- 原生编解码器为实验功能，需要另行安装 @uberscene/codecs 并设置 UBERSCENE_CODECS，默认仍走 Chrome。

- 需要 Node 22.19 或更新版本，浏览器导出依赖 headless Chrome，实际性能与资源占用未见第三方基准。

## 总结
UberScene 把“视频即代码”这个想法落到了可运行的层面：剪辑点绑定台词、代理与人类编辑同一文件、无需 FFmpeg 即可导出，这些取舍都围着“让模型更容易写视频”展开。它的完整度在同类 DSL 项目里不低，也有文档、示例和编辑器，但仍带着明显的早期项目印记——49 star、API 不稳定、部分能力还在路线图上。如果团队本来就愿意用代码管理内容生产，它值得一试；如果追求开箱即用和长期稳定，建议等 1.0。
