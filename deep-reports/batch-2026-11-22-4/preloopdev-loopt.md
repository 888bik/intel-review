## 一句话理解

它让 CI 配置不再是手写 YAML：你用熟悉的语言写工作流源码，loopt 生成标准 YAML；已有 YAML 还能导入成代码，并提交前校验“源码和生成结果是否一致”。

## 通俗解释

GitHub Actions 的 YAML 写多了会重复、难复用、难用类型检查。loopt 的思路是把工作流变成“源代码”：在 .loopt/workflows/ 用 TypeScript（默认）、Python、Go、Rust 或自定义插件语言编写，loopt gen 生成标准 .github/workflows/*.yml，生成文件带“Generated by loopt”注释提示别直接改（来源：README）。它还支持 loopt import 把现有 YAML 导入为可编辑代码、loopt gen --check 在 YAML 与源码不一致时失败、loopt lint 跑正确性与安全检查（可加 shellcheck）（来源：README Use/Review）。loopt init 会根据项目文件（package.json/Cargo.toml/go.mod/pyproject.toml 等）生成带安全默认的起点（read-only token、checkout 固定到 commit、取消过时运行）（来源：README Start a project）。24 star、MIT、v0.1.4。

## 它不是什么

1. **不是新的 CI 平台**。它生成标准 GitHub Actions YAML，仍跑在 GitHub Actions 上（来源：README）。
2. **不是必须用某一种语言**。TypeScript/Python/Go/Rust 一等支持，自定义语言走插件协议（来源：README 开头）。
3. **不是覆盖所有 YAML 编辑场景**。loopt gen 拒绝覆盖在 Loopt 之外编辑的工作流，除非 --force（来源：README Use）。
4. **不是无依赖**。生成时需要对应语言环境（Node.js 26+/Python 3/Go/Rust）（来源：README Install）。
5. **不是成熟项目**。24 star、0 fork、1 issue、v0.1.4、2026-10 创建（来源：GitHub）。

## 痛点

- **YAML 重复难维护**：用语言的代码组织能力（函数、循环、类型）写工作流。
- **已有 YAML 迁移难**：loopt import 反向导入（来源：README）。
- **源码与产物漂移**：gen --check 在 CI 中防止忘记重新生成（来源：README）。
- **安全默认**：init 生成的起点用只读 token、固定 checkout、取消过时运行（来源：README）。

## 核心功能（依据 README，注明来源）

- **多语言编写**：TypeScript/Python/Go/Rust 及自定义插件（来源：README）。
- **生成与导入**：loopt gen 生成标准 YAML；loopt import 从 YAML/复合 action 反向导入（来源：README）。
- **一致性校验**：loopt gen --check 失败于源码与 YAML 不一致（来源：README）。
- **init 智能起点**：按 package.json/Cargo.toml/go.mod/pyproject.toml 生成步骤，安全默认（来源：README）。
- **lint 审查**：正确性与安全检查，可选 shellcheck（来源：README Review）。
- **预编译二进制**：install.sh 安装到 ~/.local/bin，校验 checksum，macOS arm64/Linux x86_64（来源：README Install）。
